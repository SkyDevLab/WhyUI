WhyUI

Turn a mysterious UI state
into an explanation.

Instead of manually inspecting dozens of DOM and CSS properties, WhyUI brings the relevant browser-visible evidence together in one developer-friendly view.

01

HTML & accessibility

Checks disabled, readonly, inert, hidden and ARIA states to identify direct causes of non-interactivity.

02

CSS & layout

Examines pointer events, visibility, display, opacity, dimensions and other computed browser state.

03

Parent cascade

Walks the element hierarchy to find disabled fieldsets, inert ancestors, hidden containers and blocking parents.

04

Overlay detection

Checks whether another visible layer is intercepting the element at its viewport coordinates.

05

Form validation

Surfaces browser constraint-validation states such as required fields, type mismatch and pattern errors.

06

Live state changes

Tracks relevant DOM mutations so you can see when an element changes from enabled to disabled or back.

How it works

Inspect. Analyze. Understand.

A focused workflow designed to keep you in the page while you investigate a UI problem.

01

Select an element

Activate WhyUI and pick the UI element you want to understand.

02

Collect evidence

WhyUI inspects HTML, CSS, ancestors, overlays and validation state.

03

Explain the state

Evidence is grouped into clear confidence levels and reasons.

04

Fix with context

Use the explanation to locate the relevant condition in your application.
